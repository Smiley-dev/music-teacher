# Coding rules

These rules are mandatory. If a rule gets in the way, change the rule here (and
add an ADR if it affects architecture) instead of silently breaking it.

## Layering

- **All audio and DSP logic lives in Rust.** Capture, gain, pitch, onsets, note
  mapping, meter ballistics, smoothing and calibration math must not be
  implemented in TypeScript. React components render values they receive.
- `crates/dsp` is pure: no cpal, no Tauri, no threads, no I/O. Everything in it
  is deterministic and unit tested.
- `crates/audio-engine` talks to devices only. It does not analyse audio and
  does not know about Tauri.
- `src-tauri` glues the two together. `commands.rs` stays thin: validate
  input, call the engine or settings, map errors to `String`.
- Only `src/lib/engine.ts` calls `invoke` or creates Tauri `Channel`s. Screens
  use the hooks from `src/providers/audio-engine-context.ts` (`useEngine`,
  `useFrame`, `useSettings`, `useLatency`). Only components that draw live
  data call `useFrame`.

## Real-time audio rules

Code that runs inside a cpal data callback must never allocate, lock a mutex,
do I/O, log, or call into Tauri. Use pre-allocated buffers, atomics and `rtrb`
ring buffers. If a ring buffer is full, drop data; never block. Mark the
callback body with a `// REAL-TIME CALLBACK` comment.

Timing that matters (calibration, later Practice) uses the audio clock: cpal
`StreamInstant`s plus sample offsets. Never `Instant::now()` or UI timers.

## Rust

- Edition 2024, workspace crates under `crates/`. Shared settings go in the
  root `Cargo.toml`.
- Naming: `snake_case` functions/modules, `PascalCase` types, `SCREAMING_CASE`
  constants. Tunable numbers (thresholds, BPM, hold times) are named
  constants at the top of the module with a doc comment and unit.
- Errors: one `thiserror` enum per crate. No `unwrap`/`expect` on audio or
  engine paths; recover or report. Mutex poisoning is recovered with
  `lock().unwrap_or_else(PoisonError::into_inner)`.
- Types that cross IPC derive `Serialize` (and `Deserialize` if received) with
  `#[serde(rename_all = "camelCase")]`. Enums sent to the UI use
  `#[serde(tag = "type")]` or `rename_all` so the TypeScript side gets string
  literals.
- Code is formatted with `cargo fmt --all` (default rustfmt settings).
- `cargo clippy --workspace --all-targets -- -D warnings` must pass.

## TypeScript / React

- Files and folders are `kebab-case` (`level-meter.tsx`); components are
  `PascalCase`; a standalone hook lives in `use-*.ts` exporting
  `useSomething`. Context hooks live next to their context
  (`providers/*-context.ts`), separate from the provider component.
- Imports use the `@/` alias. No relative `../../`.
- Feature code lives in `src/features/<section>/`. A component used by more
  than one feature moves to `src/components/`.
- `src/components/ui/` is generated by shadcn (`npx shadcn@latest add <name>`).
  Do not hand-edit; wrap instead.
- Styling is Tailwind utility classes plus `cn()`. Inline `style` only for
  values computed at runtime (positions, widths). Colors use theme tokens
  (`text-muted-foreground`, `bg-muted`); semantic status colors use
  emerald (ok), amber (warning), red (error/clip).
- Types that mirror Rust live in `src/lib/engine.ts` and must match the Rust
  definitions field for field. Change both in the same commit.
- `strict` TypeScript; no `any`. Handle every variant of a status union.
- No new state library, router or styling system without an ADR.

## Errors in the UI

Every state the engine can report must have a visible, human message:
loading, no devices, permission denied, device lost (reconnecting), other
errors. Tell the user what to do, not only what failed.

## Tests

- Every pure function or struct in `crates/dsp` has unit tests in the same
  file (`#[cfg(test)] mod tests`), using synthetic signals (sines, harmonic
  tones, bursts) rather than recordings.
- New thresholds or algorithms come with a test that pins the behaviour.
- Before committing: `cargo fmt --all`, `cargo test --workspace`, clippy, and
  `npm run build`.

## Comments

- Doc comments (`///`, `/** */`) on public items and on every tunable
  constant.
- Comments explain *why*, not *what*. No commented-out code, no TODOs without
  context.

## Adding a section to the main menu

1. Create `src/features/<id>/<id>-screen.tsx` exporting `<Id>Screen`.
2. Add an entry to `SECTIONS` in `src/sections.ts` (id, label, Lucide icon,
   screen component).
3. Read audio state only through the provider hooks; never start your own
   stream.
4. Add `docs/features/<id>.md` and link it from `docs/ARCHITECTURE.md` if the
   module map changes.

## Commits

One logical step per commit, imperative subject line. Each commit builds and
passes tests.
